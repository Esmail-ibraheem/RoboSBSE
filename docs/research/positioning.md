# Positioning and related work

**No novelty is claimed.** RoboSBSE is a teaching and experimentation laboratory that brings well-known
SBSE techniques together on one small, transparent robotics substrate. We have not done a systematic
literature review, and nothing here should be read as a research contribution without one.

## How it differs from a path-planning simulator

A path-planning simulator answers *"what is a good path?"*. RoboSBSE also treats the **robot software as
the object of search**:

| Path-planning simulator | RoboSBSE |
|---|---|
| Optimises a path for a given map | Also optimises a path, but scores it by *executing controller software* in a simulator, so controller bugs and dynamics show up in the fitness |
| The planner is the product | The planner (A\*, Dijkstra) is a **reference baseline**; metaheuristics are compared to it with equal-budget statistics |
| Maps are inputs | Maps, conditions and configurations are **test inputs**, generated by search to falsify properties of the controller |
| Success = reached the goal | Explicit **test oracle** (seven properties with robustness), differential check against a reference implementation, minimised and reproducible failure records, a regression suite |
| — | Planned: program evolution (GP), genetic improvement and automated repair of the controller code itself |

## Related work this design draws on (for orientation, not exhaustive)

- **Search-based testing of cyber-physical and autonomous systems.** Procedurally generating road networks
  to test self-driving software (AsFault: Gambi, Müller, Fraser, ISSTA 2019), and the cyber-physical systems
  tool competitions at the SBST/SBFT workshops. RoboSBSE's scenario generation follows the same idea in a
  much simpler 2D world.
- **Falsification with robustness semantics.** Signal temporal logic robustness and tools such as
  S-TaLiRo and Breach minimise a quantitative robustness to find property violations. The oracle's
  normalised robustness per property, with `min` as the conjunction, is the same principle in miniature.
- **Statistics for randomised algorithms.** Arcuri and Briand's guidelines (ICSE 2011) on Mann–Whitney U and
  Vargha–Delaney A12, with many independent seeds and equal budgets. Implemented in `Statistics` and
  checked against SciPy.
- **Test-case reduction.** Delta debugging (Zeller and Hildebrandt, 2002). The greedy one-element-at-a-time
  reduction here is a simpler 1-minimal variant.
- **Metaheuristics.** Textbook formulations, e.g. Luke, *Essentials of Metaheuristics*; Eiben and Smith,
  *Introduction to Evolutionary Computing*; Kirkpatrick et al. (1983) for simulated annealing.
- **Phase 4.** Genetic programming (Koza; Poli, Langdon and McPhee, *A Field Guide to Genetic
  Programming*), genetic improvement (Langdon and Harman; Petke et al.), and automated program repair
  (GenProg: Le Goues et al.). The implementations follow these ideas in a small, simplified form.
- **Phase 5.** Random-key encodings (Bean, 1994); damped-least-squares inverse kinematics; configuration-space
  motion planning (Lozano-Pérez; textbook grid A\*); list scheduling for task allocation. They serve as
  encodings and conventional references, not as contributions.

Before using any result from this laboratory in a publication, check the literature for the specific
claim, report every configuration (the result files contain them), and use more seeds than the 15 in the
Phase 1 examples.
